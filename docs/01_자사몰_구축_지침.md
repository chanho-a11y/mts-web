## 1. 비즈니스 컨텍스트 (왜 이 사업이 특별한가)

자사몰은 "쇼핑몰 하나 더 만드는 일"이 아니라 **MTSPACE COFFEE의 비즈니스 모델을 그대로 담는 그릇**이어야 합니다. 따라서 구축 전에 비즈니스의 본질을 못박아 둡니다.

### 1.1 브랜드 정체성
- **브랜드**: MTSPACE COFFEE — "everyday excellence(매일의 탁월함)"
- **운영사**: (주)엠티에스솔루션스 / MTS Solutions Co., Ltd.
- **대표**: 홍찬호 (Chanho Hong) — 한·호주 양국 경쟁 바리스타, 14회 수상, V60 'Chanho-Tornado'로 알려짐, 광고학 학사 + MBA
- **로스터리**: 경기도 가평군 청평면 자체 로스터리. 매주 월·화 로스팅, 화·수 출고(신선도 중심). ※ 법적 판매자 주소·통신판매업 신고(인천 부평)는 별도 등록 정보 — §9 참조.
- **헤리티지**: 호주 시드니에서 공동 창업한 Normcore Coffee(2016)의 경험 → 한국 시장 재해석. 현재 "Normcore Coffee 2.0"으로 브랜드 부활 중

### 1.2 핵심 차별점 (자사몰이 반드시 살려야 할 자산)
1. **챔피언 바리스타의 전문성** — About 페이지의 수상 이력·스토리는 단순 회사소개가 아니라 **신뢰·프리미엄의 핵심 마케팅 자산**. 자사몰에서 더 강조해야 함.
2. **주 단위 로스팅 / 신선도** — "월·화 로스팅, 화·수 출고"는 강력한 약속. 배송 정책·상품 페이지·체크아웃에 일관되게 노출.
3. **B2C + B2B 동시 운영** — 일반 소비자(홈브루 125g)와 사업자(카페/레스토랑/호텔, 1kg·200g 도매)를 한 브랜드로 서비스. Shopify에서는 한 카탈로그에 섞여 불편 → **자사몰의 최대 개선 기회**.
4. **교육·컨설팅·코칭** — 원두 판매를 넘어 카페 창업 컨설팅, 바리스타 교육, 대회 코칭으로 확장하는 "파트너" 포지셔닝.

### 1.5 브랜드·도메인 전략 (v1.1 신규) — "두 얼굴, 한 몸통"

향후 두 브랜드의 역할을 명확히 나누되, **판매(커머스) 기능은 하나의 백엔드가 동시에 담당**한다.

| | NORMCORE COFFEE | MTSPACE COFFEE |
|---|---|---|
| 도메인 | **normcorecoffee.com** | **mtspace.coffee** |
| 주 고객 | **B2C (일반 소비자)** | **B2B (사업자·도매)** |
| 포지셔닝 | 경험·문화·소비자 브랜드(시드니 헤리티지, Flavour-Forward) | 로스팅·기술 토대, 도매·납품·컨설팅 파트너 |
| 주력 상품 | 소포장(125g 등), 싱글오리진, 구독, 선물 | 1kg/200g 도매, 디카페인, 정기발주, 세금계산서 |
| 가격 | 소비자가(공개) | **회원 승인 + 회원별 차등 단가** |
| 언어 | 한/영 | 한(영 병기) |

**핵심 원칙 — 단일 커머스 엔진, 멀티 스토어프론트**
- 상품·재고·SKU·주문·결제·회원은 **하나의 DB/백엔드**가 마스터. 두 도메인은 같은 엔진 위의 서로 다른 "얼굴(스토어프론트)".
- 한 번 등록한 상품을 **브랜드별 노출 설정**으로 normcore/ mtspace 어디에 보일지 제어(둘 다 가능). 재고는 공유되므로 **이중 재고·동기화 문제 원천 제거**.
- 결제는 동일 운영사((주)엠티에스솔루션스) → **이니시스·카카오페이·페이팔 결제수단을 두 도메인이 공용**. 국내(이니시스·카카오페이)는 KRW, 페이팔은 해외(외화) 채널.
- 관리자는 **한 곳에서 두 브랜드의 상품·주문·회원·정산을 통합 운영**.
- 회원/장바구니는 스토어프론트 맥락을 갖되, 같은 사람이 두 도메인을 오갈 때의 경험(통합 계정 여부)은 §2.6에서 정의.

> 비유: 주방(로스터리·재고·주문 처리)은 하나, 손님을 맞는 매장 간판은 둘(놈코어/엠티스페이스). 손님 동선과 가격표만 다르고, 뒤편 운영은 통합.

### 1.6 보유 자산 — MTSPACE 디자인 스튜디오 (v1.2 신규)

회사는 이미 강력한 콘텐츠 생산 도구를 보유하고 있다. 이를 자사몰에 녹여 **"제품 등록 = 마케팅 자산 완성"** 으로 만든다.

**현행 디자인 스튜디오** (`MTSPACE_DESIGN_STUDIO.html`, 단일 HTML ~4,000라인, html2canvas + jsPDF + JSZip + PDF.js)
- 입력: 원두 프로파일(제품명 한/영, 산지·농장·생산자·품종·가공·고도, 로스팅 레벨, 풍미노트, 추출 레시피[에스프레소/필터], 중량·포장재·보관·유통기한, 키 컬러/팔레트, 해시태그), 지식베이스·키워드 사전, label design.pdf 자동 파싱.
- 출력(4개 캔버스 + 콘텐츠):
  - **라벨** 1300×1000 (원두 봉투 전·후면, 인쇄용)
  - **카드뉴스** 1080×1080 다중 페이지 (인스타그램)
  - **썸네일** 1080×1080 (이커머스/외부채널)
  - **상세페이지** 860×가변 (25MP 초과 시 자동 분할 ZIP)
  - **블로그 글 + 관련 키워드** (텍스트 생성)
- 현재 한계: 로컬 file:// 단독 실행, 결과물이 이미지로 래스터화되어 `~/Downloads`로 떨어짐 → **자사몰·재고·상품과 연결되지 않음**. 상세·블로그까지 이미지로 만들어 **검색/AI에 약함**(텍스트가 이미지에 묻힘).

**통합 기회**: 이 도구의 템플릿·브랜드 토큰·생성 로직을 자사몰 관리자에 내장하고, **상품 레코드를 단일 입력원**으로 삼아 자산을 자동 생성·연결한다. 동시에 상세·블로그는 **이미지가 아니라 네이티브 텍스트**로 렌더해 SEO/AIEO를 강화한다(§4.6).

**보유 자산 — MTSPACE 인스타그램 카드뉴스 제작기 (v1.3 신규)** (`04_marketing/mtspace/MTSPACE_instagram_cardnews.html`, 단일 HTML ~80KB, html2canvas + Pretendard)
- 디자인 스튜디오의 단순 카드뉴스와 달리, **인스타그램 캐러셀에 특화된 더 정교한 도구**.
- **5장 서사 구조**: Hook(후킹) → Context(맥락) → Detail(향미·산지) → Experience(추출 경험) → CTA(행동유도). 브랜드 가이드(PDF P.11) 기반.
- **역할별 3개 레이아웃(A/B/C) = 15종 변형**. 슬라이드별로 즉시 전환.
- **SKU 시그널 컬러 24종**(200DPI 픽셀 실측, BRAND_TOKENS v2): 제품 선택 시 짝수 페이지 배경에 자동 적용. 밝은 컬러(6종) 위에는 검정 텍스트 자동.
- **자동 주입**: 제품 선택 시 제목·설명·농장명·가공·풍미노트가 해당 슬라이드에 자동 채움. 사용자가 직접 수정한 항목은 보호(덮어쓰지 않음).
- 출력: 1080×1350(4:5, 기본) 또는 1080×1080(1:1) PNG/JPG.
- 현재 한계: 단일 HTML·백엔드 없음, `mtspace.coffee/products.json` 라이브 페치(Shopify 의존), 작업 자동저장 없음 → **자사몰과 연결 안 됨**.

**통합 방침(대표 확정)**: 두 카드뉴스를 **모드 토글**로 공존(단순 1080×1080 / 인스타 서사 1080×1350). 데이터는 자사몰 DB 단일소스, 시그널 컬러는 `key_color` 필드(§4.6, §9 결정 반영). 두 브랜드(놈코어/엠티스페이스) 워드마크·토큰을 인식해 브랜드별로 렌더.

## 2. 이전(Migration)의 목표와 성공 기준

대표가 확정한 이전의 핵심 동기(우선순위순):

### 2.1 동기 1 — 수수료/비용 절감
- Shopify 월 구독료 + 결제 수수료 + 앱 구독료 누적 부담 제거.
- 자사몰 + 결제수단(**이니시스·카카오페이·페이팔**) 직접 정산으로 전환.
- **성공 기준**: 월 고정비를 Vercel/Supabase 사용량 기반으로 전환하여 매출 대비 플랫폼 비용률 하락. 결제 수수료는 각 PG 계약 요율로 직접 정산.

### 2.2 동기 2 — B2B 도매 기능 강화
Shopify 기본 구조로는 어려웠던 B2B 워크플로우를 자사몰의 1급 기능으로 구현.
- **사업자 회원 별도 가입·승인** (사업자등록증 확인)
- **승인 회원 전용 도매가** 노출(미승인/일반 회원에게는 도매 상품·가격 비노출 또는 "승인 필요" 표시)
- **세금계산서 발행** 연동(또는 요청 접수 → 발행 워크플로우)
- **정기 발주/재주문** (지난 주문 1-클릭 재주문, 즐겨찾는 원두 빠른 주문)
- **수량 구간별 단가**(예: 100장/500장 봉투 옵션처럼 도매 변형)
- **성공 기준**: 사업자 고객이 로그인→승인가 확인→재주문까지 사람 개입 없이 완료.

### 2.3 동기 3 — 완전한 커스터마이징
- 브랜드 스토리텔링(챔피언 이력, 로스팅 철학, 산지 스토리)을 자유롭게 구성.
- 추출 가이드, 풍미 휠, 산지 지도 등 **콘텐츠 커머스** 요소를 제약 없이 구현.
- 구독(정기배송), 선물하기, 묶음/큐레이션 등 비표준 판매 방식 자유 구현.
- **성공 기준**: 디자인/기능이 외부 테마 제약 없이 기획 의도대로 100% 구현.

### 2.4 동기 4 — SEO / AIEO / 제품 등록·마케팅 활용도 증가
- **SEO**: 서버사이드 렌더링(SSR/SSG)로 검색엔진 최적 구조, 구조화 데이터(Schema.org Product/Article/Organization), 빠른 Core Web Vitals.
- **AIEO(AI Engine Optimization / GEO)**: ChatGPT·Perplexity·Claude 등 AI 검색이 인용하기 좋은 구조 — 명확한 제품 사실표, FAQ, 자연어 설명, llms.txt, JSON-LD.
- **제품 등록 효율**: 한 번 등록한 제품 데이터를 자사몰·네이버·SNS·구글 머천트에 재활용(단일 소스).
- **마케팅 활용**: 자체 고객 DB·이메일·쿠폰·리타게팅 픽셀을 자유롭게 운영.
- **성공 기준**: 주요 키워드 노출/순위 유지·개선, AI 검색 인용 발생, 제품 1건 등록 시간 단축.

### 2.6 동기 5 — 멀티브랜드 통합 운영 (v1.1 신규)
- **두 도메인(normcorecoffee.com / mtspace.coffee)을 단일 백엔드가 동시 운영**.
- 브랜드별 디자인·콘텐츠·카탈로그 노출은 다르되, 상품·재고·주문·결제·회원·정산은 통합.
- **성공 기준**: 상품 1건 등록 → 브랜드 노출 토글만으로 양 도메인 반영. 재고는 공유되어 채널 간 불일치 0. 관리자 한 화면에서 두 브랜드 주문·정산 확인.

### 2.7 동기 6 — 회원 기반 B2B 관리 + 회원별 차등 단가 (v1.1 신규)
- **회원 가입으로 B2B 고객을 관리**(사업자 정보·승인·등급).
- **회원마다 다른 판매가** 적용 — 등급가(그룹)뿐 아니라 **특정 회원에게만 적용되는 개별 계약 단가**까지.
- 가격 우선순위(가격 해석 규칙): **① 회원 개별가 → ② 회원 등급(티어)가 → ③ 기본 소비자가** 순으로 결정.
- 미승인/비로그인 사용자에게는 도매가·도매상품 비노출(서버·RLS 레벨 차단).
- **성공 기준**: 같은 상품이 고객 A에게는 개별 계약가, 고객 B에게는 등급가, 일반 손님에게는 소비자가로 자동 노출. 운영자가 회원별 단가표를 관리자에서 설정·일괄 적용.

### 2.9 동기 7 — 제품 등록 = 콘텐츠/디자인 자동 생성 (v1.2 신규)
- 디자인 스튜디오를 관리자에 내장해, **상품 1건 등록 시 상세페이지·라벨 스티커·카드뉴스·썸네일·블로그가 자동 생성**.
- 한 번 입력한 원두 프로파일이 모든 자산의 단일 소스. 수기 반복(상세 따로, 라벨 따로, 인스타 따로) 제거.
- 텍스트 자산(상세·블로그)은 네이티브로 → SEO/AIEO 강화. 이미지 자산(라벨·카드뉴스·썸네일)은 인쇄·SNS·외부채널용으로 자동 생성·보관.
- **성공 기준**: 신규 원두 등록 후 사람이 하는 일은 "검수·승인"뿐. 상세·라벨·카드뉴스·썸네일·블로그 초안이 자동 준비되고, 상품/재고/채널과 연결됨. 제품 1건 출시 리드타임 대폭 단축.

### 2.8 비(非)목표 — 이번 범위에서 명시적으로 제외
- 글로벌 다국가 결제/통화(현 사이트의 국가선택기는 표시만 KRW 단일). **국내(KRW) 우선**, 글로벌은 후속.
- 자체 모바일 앱(웹 우선, PWA로 대응).
- 마켓플레이스(외부 입점사) 기능.

### 3.2 현행의 문제점 (자사몰에서 고칠 것)
1. **B2C/B2B 혼재** — 일반 고객에게 "1kg 사업자 전용"이 그대로 노출되어 카탈로그가 지저분하고 전환을 방해.
2. **재고 음수 다수** — 오버셀이 일상화. 신선도 비즈니스인데 "주문 후 로스팅" 모델인지, 단순 재고 미관리인지 정책 부재. 자사몰에서 **예약판매/주문제작/품절** 정책을 명확히.
3. **SKU 부재** — 대부분 variant의 sku가 비어 있음. 재고·정산·외부채널 연동의 근간이 없음. 이전 시 **SKU 체계 수립 필수**.
4. **채널 단절** — 네이버 스마트스토어와 재고·가격이 수기 동기화. 자사몰을 "단일 소스"로 만들고 동기화 전략 필요.
5. **플랫폼 종속** — 데이터·고객·디자인이 Shopify에 갇힘. 마케팅 픽셀/실험/개인화에 제약.

## 4. 자사몰 기능 요구사항 (To-Be)

### 4.1 고객 대면 (Storefront)
- **P0** 홈: 브랜드 히어로, 베스트/신상 원두, 컬렉션 진입, 브랜드 스토리 요약, 뉴스레터.

- **P0** 회원: 가입/로그인(이메일·소셜·카카오 권장), 마이페이지(주문내역, 배송조회, 주소록, 재주문).
- **P0** 검색: 상품 검색(이름·풍미·산지).
- **P0** 정책/고객지원(CS): 배송·환불·교환·개인정보·이용약관, **동적 FAQ**(§4.7), 연락처 폼.
- **P1** 구독(정기배송): 원두 정기 구독(주기·분쇄도·블렌드 선택). 신선도 비즈니스와 시너지 큼.
- **P1** 선물하기 / 메시지카드, 위시리스트.
- **P1** 리뷰/평점(포토리뷰), Q&A.

### 4.2 B2B (사업자 전용) — 동기 2의 핵심
- **P0** 사업자 회원 가입(상호·사업자번호·담당자·연락처·사업자등록증 업로드).
- **P0** 관리자 승인 워크플로우(대기→승인/반려, 승인 시 도매 카탈로그·도매가 노출).
- **P0** 도매가/등급별 가격 + **회원별 개별 단가**(승인 회원에게만). 가격 우선순위: 회원 개별가 → 등급가 → 기본가. 미승인 시 도매 상품 숨김 또는 "승인 후 구매 가능". (상세 §4.5)
- **P0** 세금계산서: 발행 요청 접수 + 사업자 정보 저장(연동 또는 수기 발행 운영).
- **P1** 1-클릭 재주문 / 즐겨찾는 품목 / 정기 발주.
- **P1** 여신/후불(필요 시), 견적서 발행.
- **P2** 도매 전용 대시보드(월 사용량, 추천 블렌드).

### 4.3 관리자 (Admin / 운영)
- **P0** 상품 관리(등록·수정·옵션·이미지·재고·가격·공개여부).

- **P0** 회원 관리(B2C/B2B, 사업자 승인).
- **P0** 재고/SKU 관리(오버셀/예약판매 정책 설정).
- **P0** 쿠폰/할인.
- **P1** 정산·매출 리포트(채널별, 기간별), 세금계산서 발행 내역.
- **P0** **동적 FAQ 관리**(질문·답변·카테고리·노출 브랜드·연결 상품 CRUD, 정렬, 게시여부). §4.7.
- **P1** 콘텐츠(블로그) 관리(Coffeelog).
- **P1** 배송 연동(택배사 송장 등록·추적).
- **P2** 생산일지/원료수불·매장 대시보드 등 **사내 시스템 연동**(이미 보유한 스킬·도구와 통합 여지).

### 4.4 마케팅/그로스 (동기 4)
- **P0** SEO 기본기: SSR/SSG, 메타·OG, sitemap.xml, robots.txt, canonical, 301 리다이렉트(기존 URL 보존).
- **P0** 구조화 데이터(JSON-LD): Organization, Product(+Offer/AggregateRating), Article, BreadcrumbList, FAQPage.
- **P0** AIEO: llms.txt, 명확한 제품 사실표, 자연어 FAQ, 인용 친화적 마크업.
- **P0** 분석: GA4, Meta Pixel, (선택) 네이버/카카오 전환 추적.
- **P1** 이메일 마케팅(뉴스레터·자동화), 쿠폰·리퍼럴.
- **P1** 외부 채널 피드: 구글 머천트, 네이버 쇼핑/스마트스토어 동기화 전략.
- **P2** 개인화·추천, A/B 테스트.

### 4.5 멀티 스토어프론트 & 회원별 차등가격 (v1.1 신규)

**멀티 스토어프론트**
- **P0** 도메인 기반 라우팅: 요청 도메인(normcorecoffee.com / mtspace.coffee)에 따라 브랜드·테마·기본 카탈로그·언어를 결정.
- **P0** 브랜드별 상품 노출 제어: 상품마다 "놈코어 노출 / 엠티스페이스 노출" 토글. 한 상품을 양쪽에 노출 가능. **재고·SKU는 공유**.
- **P0** 브랜드별 홈/디자인/콘텐츠: 놈코어=소비자 경험 중심(헤리티지·Flavour-Forward), 엠티스페이스=도매·파트너 중심.
- **P0** 통합 관리자: 한 화면에서 두 브랜드 상품·주문·회원·정산 운영. 주문·매출은 **브랜드(채널) 태그**로 구분 집계.
- **P1** 계정/장바구니 정책: 통합 계정(한 번 가입하면 양 도메인 로그인) 권장. 장바구니는 브랜드별 분리 또는 통합 — §9 결정.
- **P1** 브랜드별 결제 영수증·발신 이메일·SNS·정책 표기 분기(법적 사업자 정보는 공통).

**회원별 차등가격 (가격 해석 엔진)**
- **P0** 가격 결정 우선순위(높은 순):
  1. **회원 개별가** — 특정 회원(예: VIP 카페 거래처)에게만 적용되는 계약 단가.
  2. **회원 등급(티어)가** — '도매-기본', '도매-VIP' 등 그룹 단가.
  3. **기본 소비자가** — 비로그인/일반 회원에게 노출되는 정가.
- **P0** 운영자가 관리자에서 회원별/등급별 단가표를 설정·수정·일괄 업로드(엑셀 임포트 P1).
- **P0** 가격은 **항상 서버에서 로그인 사용자 맥락으로 재계산**. 클라이언트가 보낸 가격 불신. 장바구니·체크아웃·주문에 적용된 단가의 근거(개별가/등급가/정가)를 기록.
- **P0** 노출 차단: 비승인·비로그인에게 도매가/도매상품이 화면·API·검색·사이트맵 어디에도 노출되지 않음(RLS 강제).
- **P1** 회원별 할인율(품목군 단위), 최소주문수량(MOQ), 결제조건(선결제/후불) 차등.

### 4.6 디자인 스튜디오 통합 — 제품등록→자산 자동생성 (v1.2 신규)

**입력 (단일 소스: 상품 레코드)**
- **P0** 상품 등록 폼에 원두 프로파일 필드 일체 수용: 제품명(한/영), 산지(국가·지역·농장·생산자), 품종, 가공, 고도, 로스팅 레벨, 풍미노트, 추출 레시피(에스프레소/필터), 중량·포장재·보관·유통기한, **키 컬러/팔레트**, 해시태그, 판매자 정보.
- **P0** 이 데이터가 모든 자산 생성의 단일 입력원. (기존 스튜디오의 입력 항목과 1:1 매핑)

**텍스트 자산 — 네이티브 렌더(SEO/AIEO)**
- **P0** **상세페이지**: 제품 데이터 → 구조화된 상품 상세(풍미·로스팅·산지·가공·추출 표 + 본문)로 자동 구성. 이미지가 아닌 **HTML 텍스트**. JSON-LD 동반.
- **P1** **블로그(Coffeelog) 초안**: 제품·지식베이스·브랜드 보이스 기반 초안 + 관련 키워드 자동 생성 → 검수 후 발행. AIEO 친화(사실표·FAQ·자연어).
- **P0** 사실 검증: 생성 텍스트는 지식베이스 대조(허위·과장 차단) 후 사람 승인.

**이미지 자산 — 브랜드 템플릿 렌더 후 래스터화(인쇄/SNS/외부채널)**
- **P0** **라벨 스티커**(1300×1000, 인쇄·PDF), **썸네일**(1080×1080, 목록/외부채널).
- **P0** **카드뉴스 — 두 모드 토글**(v1.3):
  - *단순 모드*: 1080×1080 단일/소수 페이지(빠른 제작).
  - *인스타 서사 모드*: 1080×1350(또는 1:1), **Hook→Context→Detail→Experience→CTA 5장**, 역할별 3레이아웃(15종), **SKU 시그널 컬러(key_color)** 자동 적용, 풍미노트·농장명·가공·설명 자동주입(수동 편집 보호).
  - 관리자에서 버튼으로 모드 전환. 두 모드 모두 **자사몰 DB 단일소스**에서 데이터를 읽고, 현재 **브랜드(놈코어/엠티스페이스) 워드마크·토큰**을 인식.
- **P0** 생성 자산은 **상품에 연결·버전관리**되어 Storage 보관. 상태(초안/생성중/완료/발행).
- **P1** 자산 재생성(프로파일 수정 시 변경분만), 일괄 생성, 외부채널(네이버·인스타) 내보내기, 슬라이드별 레이아웃 전환·텍스트 미세조정.

**운영 흐름**
- **P0** 제품 등록/수정 → 생성 작업 큐 → 자산 생성 → **검수·승인 게이트** → 발행(자사몰 노출/채널 피드).
- **P1** 생성 모드: 자동(등록 즉시) vs 수동(버튼). 부분 재생성. 템플릿 버전 관리.
- 상세 기술 설계(서버 렌더링·템플릿 공유·큐)는 03 기술사양서 §14.

### 4.7 CS 동적 FAQ (v1.4 신규)

정적 안내문이 아니라 **데이터 기반으로 검색·분류·자동반영되는 FAQ**로 CS 부하를 줄이고 SEO/AIEO(FAQPage)를 강화한다.

- **P0** FAQ 데이터화: 질문·답변을 DB로 관리(관리자 CRUD). 카테고리(주문/배송/교환·환불/제품/도매/계정 등), 정렬, 게시여부.
- **P0** 검색·필터: 키워드 검색 + 카테고리 필터. 자주 찾는 질문 상단 노출.
- **P0** 맥락 노출(동적): 상품 상세에는 해당 **상품·카테고리 연결 FAQ**, 배송정책 페이지에는 배송 FAQ가 자동 노출. **신선도·로스팅/출고 일정·배송비 등 변수는 단일 소스에서 주입**(요일·금액 변경 시 FAQ 자동 갱신).
- **P0** 브랜드/스토어프론트 인식: 놈코어(B2C)·엠티스페이스(B2B)에 맞는 FAQ 셋(도매·세금계산서 FAQ는 B2B에서만).
- **P0** 구조화 데이터: **FAQPage JSON-LD** 자동 출력(검색·AI 인용). AIEO 친화 자연어.
- **P1** 자동 초안: CS 문의(연락처 폼)·반복 질문에서 FAQ 후보 추천, 제품/지식베이스 기반 답변 초안 → 검수 후 게시.
- **P1** "도움이 됐나요?" 피드백, 미해결 시 연락처 폼 연결.
- **성공 기준**: 반복 문의가 FAQ로 흡수되어 CS 문의량 감소, 상품/정책 변경이 FAQ에 자동 반영, FAQ가 검색·AI 답변에 인용.

## 5. 운영 원칙 (구축·운영 전반에서 지킬 규칙)

1. **단일 소스 원칙** — 제품·재고·가격은 자사몰 DB가 마스터. 네이버 등 외부 채널은 동기화 대상이지 별도 진실이 아님.
2. **SKU 우선** — 모든 판매 단위(블렌드×중량×분쇄도 등)는 고유 SKU를 가진다. SKU 없는 상품 등록 금지.
3. **신선도 약속의 일관성** — 로스팅/출고 일정(월·화 로스팅, 화·수 출고)은 상품·배송정책·체크아웃·주문메일에 동일하게 표기.
4. **B2C/B2B 명확 분리** — 일반 고객 경험에 도매 상품/가격이 새어나가지 않게 한다.
4-1. **브랜드는 얼굴, 백엔드는 하나** — 두 도메인은 같은 커머스 엔진의 스토어프론트. 상품·재고·주문·회원은 통합, 노출·가격·디자인만 분기.
4-2. **가격은 서버가 회원 맥락으로 결정** — 회원 개별가 → 등급가 → 정가 순. 노출 화면이 아니라 서버가 최종 단가의 단일 결정자.
4-3. **제품 데이터가 자산의 단일 소스** — 라벨·카드뉴스·썸네일·상세·블로그는 모두 상품 레코드에서 파생. 자산을 따로 손보지 말고 제품 데이터를 고친 뒤 재생성한다.
4-4. **텍스트는 네이티브, 이미지는 자산** — 검색·AI가 읽어야 하는 상세·블로그 본문은 HTML 텍스트로(이미지 금지). 인쇄·SNS용 라벨·카드뉴스·썸네일만 이미지로 래스터화.
4-5. **자동 생성에는 검수 게이트** — 자동 생성물은 사람 승인 전 발행하지 않는다(특히 텍스트 사실 검증).
5. **법적 필수 준수** — 전자상거래법(통신판매업), 개인정보보호법, 전자금융거래(PG), 부가세(세금계산서). 푸터의 사업자 정보·통신판매업 신고번호는 전 페이지 유지.
6. **데이터 보호** — 사업자등록증·개인정보는 접근통제(RLS)·암호화·최소수집. 결제정보는 자체 저장 금지(PG 위임).
7. **점진적 전환** — 빅뱅 금지. 데이터 이전→스테이징 검증→소수 트래픽→전환→Shopify 병행 종료의 단계적 컷오버.
8. **측정 가능성** — 모든 핵심 기능은 분석 이벤트를 동반(장바구니·결제·가입·승인·재주문).

5. **Phase 4 — 마케팅/그로스(상시)**: AIEO·이메일·채널 피드·구독·리뷰.
6. **컷오버**: 스테이징 검증 → 소프트 런칭 → DNS 전환 → Shopify 결제 중단.

## 9. 의사결정 대기 항목 (다음 단계에서 확정 필요)

- [ ] **재고 정책**: 오버셀 허용 vs 예약판매(주문 후 로스팅) vs 실재고 품절 — 비즈니스 표준 확정.
- [ ] **SKU 체계**: 코드 규칙(브랜드-라인-원두-중량-분쇄도) 정의.
- [ ] **분쇄도 옵션 범위**: 원두/홀빈만 vs 분쇄(에스프레소·드립·프렌치프레스 등) 제공.
- [ ] **구독(정기배송) 도입 시점**: P1으로 당길지.
- [ ] **세금계산서**: 자동 발행 연동(예: 팝빌/바로빌) vs 수기 발행.
- [ ] **네이버 스마트스토어**: 유지·동기화 vs 단계적 통합.
- [ ] **카카오 로그인/알림톡** 도입 여부.
- [ ] **디자인 방향**: 현행 톤 유지 vs 리뉴얼.
- [ ] **통합 계정**: 한 회원이 양 도메인 공통 로그인(권장) vs 도메인별 분리 계정.
- [ ] **장바구니 범위**: 브랜드별 분리 vs 도메인 간 통합 장바구니.
- [ ] **브랜드별 판매 경계**: 놈코어(B2C)·엠티스페이스(B2B) 외에, 양쪽에 동시 판매할 품목 범위(예: 싱글오리진을 소비자가로 놈코어, 도매가로 엠티스페이스에 동시 노출).
- [ ] **회원 개별가 운영 방식**: 관리자 수기 입력 vs 엑셀 일괄 업로드 vs 둘 다.
- [ ] **normcorecoffee.com 이전**: GoDaddy → 자사 백엔드로 완전 이전 시점(브랜드 사이트 콘텐츠 마이그레이션 포함).
- [ ] **자산 생성 방식**: 서버 자동 렌더(권장, 무인 배치) vs 관리자 브라우저 렌더(기존 html2canvas 재사용) vs 혼합.

**D-112 후속 잔여 항목 (2026-08-11 · 주문 귀속 결함 복구 이후)**
- [ ] **`orders.storefront_id` NOT NULL 제약 도입 여부**: 배포(2026-08-11) 후 1주 무결함 확인 뒤 결정. 지금 걸면 앱이 값을 못 보내는 순간 체크아웃이 500 으로 죽는다. 확인 시점 = 2026-08-17 회귀 감시.
- [ ] **실주문 1건으로 앱 INSERT 경로 최종 확인**: 현재는 DB 안전망 트리거가 보정해도 결과가 같아 앱이 실제로 두 컬럼을 쓰는지 구분되지 않는다. `alter table public.order_item disable trigger trg_fill_order_storefront;` 로 잠시 끄고 테스트 주문 1건 → 값 확인 → 다시 enable.
- [ ] **anon 쓰기 grant 정리 여부**: `public` 스키마 **44개 테이블 전부**에 `anon`·`authenticated` 의 INSERT/UPDATE/DELETE 테이블 권한이 남아 있다(Supabase 기본 부여). 현재 44개 모두 RLS 가 켜져 있어 정책 없는 명령은 차단되므로 **악용 경로는 아니다**. 다만 **RLS 를 한 테이블에서라도 끄는 순간 즉시 익명 쓰기가 열린다** — 권한 자체를 회수해 이중 방어로 갈지 결정 필요. (관련: D-097 뷰 권한 회수)
- [ ] **혼합 브랜드 장바구니 / 멀티 스토어프론트 판매**: 현재 안전망 트리거는 상품의 판매등록 스토어프론트가 **유일할 때만** 귀속하고 모호하면 NULL 로 남긴다. 한 상품을 두 스토어프론트에 동시 판매하거나 장바구니에 두 브랜드를 섞는 순간 트리거 재설계가 필요하다(정본은 앱의 명시 INSERT 이므로 앱은 영향 없음).
