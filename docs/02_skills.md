# MTSPACE × NORMCORE Commerce 스킬

이 스킬은 Claude가 MTSPACE COFFEE × NORMCORE COFFEE 멀티브랜드 자사몰 프로젝트를 도울 때 **무엇을 먼저 읽고, 어떤 순서로 일하고, 무엇을 절대 어기면 안 되는지**를 정의한다.

## 0. 항상 먼저 할 일 (Bootstrapping)

작업 시작 전 기준 문서를 읽는다. 충돌 시 우선순위는 **handoff → 의사결정 로그 → 01 → 03 → 02**(현재상태 > 확정결정 > 비즈니스 > 기술 > 작업규칙)이다.

0. (루트) `MTSPACE COFFEE_NORMCORE COFFEE_handoff.md` — 통합 진입점(현재 상태·자산 맵). 그리고 `MTSPACE COFFEE_NORMCORE COFFEE.md` — 의사결정 로그(확정 결정·근거).
1. `01_자사몰_구축_지침.md` — 비즈니스 컨텍스트·요구사항·우선순위(P0/P1/P2)·운영 원칙.
2. `03_기술사양_명세서.md` — 아키텍처·DB 스키마·API·마이그레이션·일정.
3. 코드 작업이면 레포의 `README`, `package.json`, `supabase/migrations/`, 기존 스키마를 확인.

읽지 않고 추측해서 구조를 만들지 않는다.

## 1. 프로젝트 핵심 사실 (암기)

- **운영사**: (주)엠티에스솔루션스 · 사업자번호 653-81-02761 · 대표 홍찬호 · 통신판매업 제2022-인천부평-2097호. **로스터리=경기도 가평군 청평면**. ※ 법적 판매자 주소(인천 부평)는 별도 등록정보로 갱신 여부 미정(01 §9). **두 브랜드(MTSPACE/NORMCORE) 모두 동일 법인** → PG·세금·정책 공통.
- **스택**: Next.js(App Router, SSR/SSG) + Supabase(Postgres·Auth·Storage·RLS) + Vercel. 결제는 **멀티 PG: 이니시스(국내 표준결제창)·카카오페이(간편결제)·페이팔(해외/외화)**, 두 도메인 공용.
- **멀티브랜드 / 멀티 스토어프론트**: **하나의 백엔드가 두 도메인을 동시 운영**.
  - **normcorecoffee.com = NORMCORE COFFEE = B2C(소비자)** — 현재 GoDaddy 정적 사이트(판매 기능 없음, mtspace로 링크). 시드니 헤리티지·Flavour-Forward.
  - **mtspace.coffee = MTSPACE COFFEE = B2B(사업자·도매)** — 로스팅·기술 토대, 도매·컨설팅.
  - 상품·재고·SKU·주문·결제·회원은 **공유(단일 마스터)**. 도메인은 같은 엔진의 다른 "얼굴". 노출·가격·디자인·언어만 분기.
- **통화/세금**: KRW 단일, **부가세 포함 표시**.
- **신선도 약속**: 주 **월·화 로스팅**, 화·수 출고. 상품·배송정책·체크아웃·주문메일·FAQ에 일관 표기(단일 소스에서 주입).
- **두 고객군 + 회원별 차등가격**: B2C(소비자가) + B2B(승인 회원). 가격 우선순위 **① 회원 개별가 → ② 등급(티어)가 → ③ 기본 소비자가**. 미승인/비로그인엔 도매 비노출.
- **채널**: 자사몰(마스터, 2도메인) + 네이버 스마트스토어(normcorecoffee, 동기화 대상) + Instagram(@mtspacecoffee/@normcore_coffee)/YouTube.
- **디자인 스튜디오 내장(v1.2)**: 기존 `MTSPACE_DESIGN_STUDIO.html`(라벨·카드뉴스·썸네일·상세·블로그 생성)을 관리자에 통합. **상품 레코드 1건이 모든 자산의 단일 입력원**. 제품 등록 → 자산 자동 생성 → 검수 → 발행.
  - 텍스트 자산(상세·블로그) = **네이티브 HTML 렌더(SEO/AIEO)**. 이미지로 굽지 않는다.
  - 이미지 자산(라벨 1300×1000·카드뉴스 1080×1080 다중·썸네일 1080×1080) = 브랜드 템플릿 렌더 → 래스터화(인쇄/SNS/외부채널).
  - 브랜드 토큰: `--brand/--key`(제품 키컬러), `--grad`, grey 스케일. 기존 스튜디오의 디자인 시스템 계승.
- **인스타 카드뉴스 엔진(v1.3)**: 기존 `MTSPACE_instagram_cardnews.html`을 카드뉴스 엔진으로 흡수. 관리자에서 **두 모드 토글**(단순 1080×1080 / 인스타 서사 1080×1350).
  - 서사 구조: **Hook→Context→Detail→Experience→CTA 5장**, 역할별 3레이아웃(A/B/C, 총 15종).
  - **SKU 시그널 컬러 = product.key_color**(24종 실측, BRAND_TOKENS v2). 밝은 컬러(luminance>0.6) 위엔 검정 텍스트 자동.
  - 자동주입: 제목·설명·농장명(farmName)·가공·풍미노트(최대5) → 해당 슬라이드. **사용자 수정분(dirty)은 덮어쓰지 않음**.
  - 데이터는 **자사몰 DB 단일소스**(products.json 라이브 페치 폐기). 브랜드(놈코어/엠티스페이스) 워드마크·토큰 인식.

## 2. 불변 규칙 (Never break)

1. **데이터 단일 소스**: 상품·재고·가격·회원의 진실은 자사몰 DB. 두 도메인·외부 채널은 모두 이 마스터를 바라본다.
2. **SKU 필수**: 판매 단위(블렌드×중량×분쇄도 등)마다 고유 SKU. SKU 없는 variant 생성 금지. **재고는 SKU 단위로 공유**(브랜드/도메인이 달라도 같은 SKU면 같은 재고).
3. **B2C/B2B 누수 금지**: 미승인/일반 고객 화면·API 응답·검색·사이트맵에 도매 상품·도매가가 노출되면 안 된다. 서버/RLS 레벨에서 막는다(클라이언트 숨김만으로 끝내지 않는다).
3-1. **브랜드/스토어프론트 격리**: 상품의 브랜드 노출 플래그를 서버에서 강제. normcore에 미노출 상품이 normcore 도메인의 목록·검색·사이트맵·API에 나오면 안 된다(반대도 동일). 도메인은 미들웨어에서 Host로 식별하고, 그 맥락을 모든 쿼리에 전달한다.
3-2. **가격 해석은 서버 단일 결정**: 단가는 항상 서버에서 **로그인 사용자 + 브랜드 맥락**으로 `① 회원 개별가 → ② 등급가 → ③ 기본가` 순으로 산출. 클라이언트가 보낸 가격으로 장바구니/결제 확정 금지. 적용 단가의 근거(개별/등급/정가)를 주문에 기록.
3-3. **제품이 자산의 단일 소스**: 라벨·카드뉴스·썸네일·상세·블로그는 상품 레코드에서 파생. 자산 파일을 직접 수정하지 말고 제품 데이터를 고친 뒤 재생성한다.
3-4. **텍스트는 네이티브, 이미지만 래스터**: 상세·블로그 본문은 검색·AI가 읽도록 HTML 텍스트로 렌더(이미지에 정보 묻기 금지). 라벨·카드뉴스·썸네일만 이미지로 굽는다.
3-5. **자동 생성물엔 검수 게이트**: AI/자동 생성 텍스트·이미지는 사람 승인 전 발행하지 않는다. 텍스트는 지식베이스 사실검증 후 발행.
3-6. **카드뉴스 브랜드 룰 불가침**(인스타 엔진 계승): 워드마크(`.wm`)·페이지번호·서브타이틀은 폰트크기 슬라이더와 무관하게 고정(`*0.7`), 폰트는 항상 Helvetica Neue. 폰트 크기는 px 금지·**cqi 단위**(1080×1350 비율 보존). 밝은 시그널 위 검정 텍스트(안티패턴 #2). 사용자 수정 텍스트(`dirty`) 자동덮어쓰기 금지. Brand Blue 외 색을 기본 폴백으로 쓰지 않음.
4. **결제정보 자체 저장 금지**: 카드/계좌 등 민감 결제정보는 각 PG(이니시스·카카오페이·페이팔)에 위임. 우리 DB엔 거래 식별자·상태·결제수단(provider)만.
5. **금액은 정수(원) + 서버 신뢰**: 가격·합계·할인은 서버에서 재계산. 클라이언트가 보낸 금액을 신뢰해 결제 승인하지 않는다.
6. **SEO 보존**: URL 변경 시 301 매핑 동반. 기존 `/products/`, `/collections/`, `/blogs/` 경로를 깨뜨리지 않는다.
7. **RLS 기본 ON**: 모든 사용자 데이터 테이블은 Row Level Security 활성 + 정책 명시. service_role 키는 서버에서만.
8. **법적 표기 유지**: 사업자 정보·통신판매업 신고번호·정책 링크는 전 페이지 푸터에 유지.
9. **개인정보·사업자등록증**: 최소수집·접근통제·암호화. Storage 버킷은 비공개 + 서명 URL.
10. **파괴적 작업 확인**: 운영 DB 마이그레이션, 대량 상품/주문 변경, 결제 모드 전환 전 반드시 사용자 확인 + 롤백 계획.

## 3. 작업 유형별 플레이북

### 3.1 상품/카탈로그 작업
- 모델: `product` → `product_variant`(SKU, 중량, 분쇄도, 가격, 재고, 도매여부) → `product_option`. 풍미노트·로스팅레벨·산지·가공·추천추출은 **구조화 필드**로(본문 자유텍스트에 묻지 않는다).
- 카테고리: Blends / Single Origins / 디카페인 / Normcore / (B2B 별도). 현 Shopify의 태그·제목 규칙을 속성으로 정규화.
- 등록 시 JSON-LD(Product/Offer)와 OG 메타가 자동 생성되는지 확인.
- 재고 정책 필드(오버셀/예약판매/품절)를 명시. 음수 재고를 무의식적으로 허용하지 않는다.

### 3.2 결제(멀티 PG: 이니시스·카카오페이·페이팔) 작업
- 공통 흐름: 주문 생성(pending) → 선택한 PG 결제창/리다이렉트 → 인증/승인 콜백 → **서버에서 승인·검증(금액·주문·통화 일치)** → 주문 paid → 재고 차감 → 완료. 실패/취소/타임아웃 분기 모두.
- **provider 추상화**: `payment.provider`('inicis'|'kakaopay'|'paypal')로 어댑터 분기. 주문/결제 모델은 PG 중립, 각 어댑터가 서명·승인·취소 API 차이를 흡수.
- 이니시스: INIStdPay 표준결제창 + 서버 승인(SHA256 서명, 망취소). 카카오페이: ready→approve(pg_token) 2단계(또는 이니시스 경유 간편결제). 페이팔: Orders v2 create→capture, **통화(USD 등)·환율·해외배송** 고려.
- 부분취소·환불·망취소(승인 후 통신 실패)를 PG별로 모두 다룬다.
- 테스트는 각 PG 샌드박스/테스트 상점으로. 운영 전환은 사용자 확인 후.
- 멱등성: 동일 결제 콜백 중복 수신에도 이중 처리 금지(주문/거래 unique + 상태 가드).
- 통화 일관성: 국내(이니시스·카카오페이)=KRW, 페이팔=외화. 주문에 통화 기록, 금액 검증은 통화 단위로.

### 3.3 B2B 작업
- 가입: 상호·사업자번호·담당자·연락처·사업자등록증(Storage). 상태 `pending`.
- 승인: 관리자 `approved`/`rejected`. 승인 시 `customer_type='b2b'` + 가격등급 부여.
- 가격: 등급가(`variant_prices` by tier) + **회원 개별가(`customer_variant_prices` by profile)**. 노출은 승인+로그인 한정(RLS).
- 세금계산서: 사업자 정보 저장 + 발행요청. 자동연동(팝빌 등) 또는 수기 운영 — 01 지침의 미결정 항목 확인.
- 재주문/정기발주: 과거 주문 → 장바구니 복제. 자주 쓰는 품목 즐겨찾기.

### 3.3-1 멀티 스토어프론트(두 도메인) 작업
- 도메인 식별: Next.js 미들웨어가 Host 헤더로 `storefront`(normcore/mtspace) 결정 → 브랜드·테마·기본카탈로그·언어 컨텍스트 주입. 모든 데이터 쿼리는 이 컨텍스트를 받는다.
- 상품 노출: `product`에 브랜드별 노출 플래그(또는 `product_storefronts` 매핑). 목록·검색·사이트맵·JSON-LD 모두 현재 스토어프론트 기준으로 필터.
- 공유/분리: 재고·SKU·주문·결제·회원은 **공유**. 디자인·홈·콘텐츠·발신메일·SNS·정책표기(법인정보 제외)는 **브랜드별 분기**.
- 주문/매출: 주문에 `brand`/`storefront` 태그를 남겨 브랜드별 집계가 가능하게.
- 로컬 개발: 호스트 시뮬레이션(예: `normcore.localhost`, `mtspace.localhost`)으로 도메인 분기 테스트.

### 3.3-2 회원별 차등가격(가격 해석 엔진) 작업
- 단일 함수/서비스로 가격 해석을 캡슐화: `resolvePrice(variant, profile, storefront) → {price, source}`.
  - 우선순위: `customer_variant_prices`(개별) → `variant_prices`(등급) → `variant.base_price`(정가).
  - 비로그인/일반 회원 → 정가. 승인 B2B → 등급/개별가.
- DB 레벨에서도 가능하면 SQL 함수/뷰로 동일 로직 재현(목록 N+1 방지, RLS와 정합).
- 장바구니·견적·체크아웃·주문 항목에 **적용 단가 + 근거(source) + 시점 스냅샷**을 저장.
- 관리자: 회원별/등급별 단가표 CRUD. (P1) 엑셀 일괄 임포트. 변경 시 audit_log.
- 절대: 클라이언트가 계산/전송한 가격으로 결제 승인하지 않는다.

### 3.3-3 디자인 스튜디오 / 자산 자동생성 작업 (v1.2)
- 단일 소스: 상품 등록/수정 폼이 원두 프로파일(제품명 한/영·산지·농장·생산자·품종·가공·고도·로스팅·풍미노트·추출 레시피·중량·포장·보관·유통기한·**키 컬러**·해시태그)을 모두 수용. 기존 스튜디오 입력 항목과 1:1 매핑(03 §14.2).
- 파이프라인: `상품 저장 → generation_job 큐 → 자산 생성 → product_asset/content_draft 저장(Storage·DB) → 검수·승인 → 발행`.
- 텍스트 자산(상세·블로그): **공유 React 템플릿으로 네이티브 렌더**. 블로그 초안은 제품+지식베이스로 생성 후 사실검증·사람 승인. JSON-LD 동반.
- 이미지 자산(라벨·카드뉴스·썸네일): **브랜드 템플릿(공유 컴포넌트) → 서버 렌더(Satori/@vercel/og 또는 Playwright)** 로 PNG/PDF. 기존 html2canvas 파이프라인은 관리자 브라우저 수동 모드 폴백.
- 기존 도구 이식: `MTSPACE_DESIGN_STUDIO.html`의 템플릿·치수·브랜드 토큰·캔버스 스펙(label 1300×1000@3×, post/thumb 1080×1080@2×, detail 860×가변@3×, 25MP 분할)을 React 컴포넌트로 포팅. 래스터 이슈(onclone CSS 무시·가장자리 띠·addColorStop)는 mtspace-design-studio 스킬의 회고를 참조.
- 검증: 생성 이미지는 가장자리·해상도·25MP 한도 확인. 텍스트는 사실·브랜드보이스·SEO 메타 확인.
- 절대: 자산을 손으로 덮어쓰지 말 것(제품 재생성으로 처리), 텍스트 정보를 이미지에 묻지 말 것, 미검수 자동발행 금지.

### 3.3-4 인스타 카드뉴스 엔진 작업 (v1.3)
- 레퍼런스: `MTSPACE_instagram_cardnews.html` + `CARDNEWS_TECH_DOCS.md` + `mtspace-cardnews-builder` 스킬. 작업 전 먼저 읽는다.
- 구조 계승: 5장 역할(Hook/Context/Detail/Experience/CTA) × 3레이아웃(A/B/C). 역할·레이아웃은 데이터(`asset_template.spec`)로 관리.
- 데이터 소스 전환: 기존 `mtspace.coffee/products.json` 라이브 페치 → **자사몰 product 레코드**. SKU 정규식 매칭은 마이그레이션 시드용으로만; 런타임은 `product.key_color` 사용.
- 자동주입 매핑(계승): `data-fill`(title/description/farm/process/now-farm) + `data-tn`(풍미노트 0~4). farmName()·parseTastingNotes() 로직 이식. dirty 보호 유지.
- 폰트 시스템: `--fs-head/--fs-body`(기본 0.8/0.7, 50~200%), 브랜드 chrome 4요소는 `*0.7` 고정. 폰트 패밀리 4종, 워드마크는 Helvetica Neue 유지.
- 모드 토글: 단순(1080×1080) ↔ 인스타 서사(1080×1350). 출력 크기·레이아웃 분기.
- 브랜드 인식: 현재 스토어프론트(놈코어/엠티스페이스)에 맞는 워드마크·토큰·CTA.
- 포팅: 단일 HTML→React 컴포넌트(템플릿·cqi·테마). "단일 HTML/백엔드 금지" 원칙은 자사몰 통합 시 **폐기**(설계 규칙만 계승). 기존 HTML은 빠른 수동 도구로 병행 가능.
- 검증: 1080×1350 출력 비율, 워드마크 크기 불변, 밝은 시그널 검정텍스트, dirty 보호, 헤드리스 픽셀 검증(mtspace-cardnews-builder §3 체크리스트).
