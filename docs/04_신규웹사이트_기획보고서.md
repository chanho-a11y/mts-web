> 목적: 현행 Shopify 사이트(mtspace.coffee)를 **전수 조사**하여 구조·구성요소·데이터 흐름을 규명하고, 그 위에 지침·기술사양에 따른 **신규 통합 웹사이트(놈코어 B2C + 엠티스페이스 B2B)** 의 페이지·기능·IA·데이터 흐름을 기획·보고한다.

## 1. 요약 (Executive Summary)

현행 mtspace.coffee는 Shopify 기반의 **단일 브랜드·B2C/B2B 혼재** 스토어로, 약 13개 페이지 + 4개 컬렉션 + 27개 상품 + Coffeelog 블로그로 구성된다. 이미 **AIEO(agents.md·UCP/MCP·AI 디스커버리 사이트맵)** 와 다국가 선택기(표시만 KRW)가 적용돼 있고, 네이버 스마트스토어를 병행 채널로 운영한다. 콘텐츠 자산(라벨·카드뉴스·상세) 생산 도구(디자인 스튜디오·인스타 카드뉴스 제작기)와 마케팅 KB도 별도 보유한다.

전수분석에서 드러난 핵심 개선점은 다섯 가지다: ① **B2C/B2B 혼재**(도매 상품이 일반 카탈로그에 노출), ② **FAQ 분산**(페이지 1 + 블로그 3곳 중복), ③ **SKU 부재·음수 재고**(정산·동기화 기반 취약), ④ **상세정보의 이미지 매몰**(SEO/AIEO 약점), ⑤ **플랫폼 종속**(데이터·고객·디자인이 Shopify에 갇힘, 콘텐츠 도구가 사이트와 단절).

신규 사이트는 **단일 Next.js+Supabase 백엔드가 두 도메인(normcorecoffee.com=B2C, mtspace.coffee=B2B)을 운영**하고, 제품 등록 한 번으로 상세·라벨·카드뉴스·블로그·인스타 자산이 자동 생성되며, 회원별 차등가격·멀티 PG(이니시스·카카오페이·페이팔)·CS 동적 FAQ를 1급 기능으로 갖춘다.

### 2.3 핵심 구성요소(컴포넌트) 분해

- **헤더**: 로고/워드마크, 메인 내비, 로그인 진입, **국가/지역 선택기(23개국, 표시만 KRW)**, 검색, 장바구니 드로어.
- **히어로**: 풀블리드 다중 이미지 + 카피("welcome to MTSPACE COFFEE", "everyday excellence", "from Sydney to Seoul").
- **컬렉션 카드 그리드**: 이미지+제목+요약, 컬렉션 진입.
- **상품 카드**: 썸네일, 제목, 정가/할인가, 단가/단위 표기.
- **상품 상세**: 이미지 갤러리, 가격(세금포함 안내), 수량 스테퍼, 장바구니, **리치 본문(풍미노트·로스팅레벨·중량·추천추출 구조)**, **추가 정보 이미지 다수(브루가이드·배송안내가 이미지로 매몰)**, 공유, **네이버 스마트스토어 아웃링크**.
- **필터/정렬**: 가격 슬라이더, product type(블렌드/싱글오리진), 정렬 9종.
- **뉴스레터**: 이메일 수집 폼.
- **푸터**: **판매자 정보(법정: (주)엠티에스솔루션스·653-81-02761·통신판매 제2022-인천부평-2097호·인천 부평 주소·대표번호)**, SNS, 정책 링크, Powered by Shopify.
- **연락처 폼**: 이름·이메일·전화·문의.

### 2.4 데이터 흐름 (As-Is)

```
[Shopify 백엔드]
  products(27)·variants·collections(태그/제목 규칙)·customers·orders·blog·pages·metafields·markets
        │  (Liquid 테마 렌더)
        ▼
[storefront HTML]  ──상품/컬렉션/페이지/블로그/정책
        │
        ├─ /products.json, /collections/*/products.json  ──(CORS *)──▶ 사내 카드뉴스 도구·마케팅 에이전트가 직접 fetch
        │
        ├─ 체크아웃 ──▶ Shopify 호스팅 체크아웃(결제)
        ├─ 고객계정 ──▶ Shopify 신규 고객계정(무비밀번호, shopify.com)
        ├─ AIEO ──▶ agents.md · UCP/MCP · sitemap_agentic_discovery
        └─ 네이버 스마트스토어 ◀─수기 동기화─▶ (재고·가격 이중관리)
```

데이터의 **진실은 Shopify**에 있고, 사내 콘텐츠 도구·네이버는 이를 **읽기/수기 복제**한다. 사이트와 콘텐츠 생산이 단절돼 있어, 제품 1건을 내려면 Shopify 등록 → 카드뉴스 도구 별도 작업 → 네이버 별도 등록의 3중 수작업이 발생한다.

### 2.5 확인된 문제점 (개선 기회)

1. **B2C/B2B 혼재** — `/collections/all`에 1kg 도매 상품·도매가가 일반 고객에게 노출.
2. **FAQ 분산·중복** — `/pages/faq` + 블로그 'FAQ' + 블로그 '자주 묻는 질문' + `/blogs/.../faq` 4중 산재 → 유지보수·검색 비효율.
3. **컬렉션 규칙 취약** — 싱글오리진을 **제목 문자열 'singular 오리진' 포함**으로 잡는 등 깨지기 쉬운 규칙.
4. **SKU 부재·음수 재고** — variant SKU 공란, 재고 음수 다수(오버셀 일상화) → 정산·채널 동기화 기반 부재.
5. **상세정보 이미지 매몰** — 브루가이드·배송안내·풍미정보 일부가 이미지로 들어가 **검색·AI가 못 읽음**.
6. **정크/앱 잔재** — cats·test 미발행, AVADA HTML 사이트맵 6종.
7. **플랫폼 종속** — 고객계정·체크아웃·데이터가 Shopify에 귀속, 콘텐츠 도구와 단절.

### 2.6 살려야 할 자산(강점)

- **브랜드 서사·대표 이력**(수상 19건, Sydney→Seoul) — 프리미엄·신뢰의 핵심.
- **신선도 운영**(주 단위 로스팅, oldest-batch≤7일, 신선 요청 옵션, 롯데택배).
- **서비스 라인업**(컨설팅·파트너십·코칭·계약로스팅) — 단순 판매를 넘는 B2B 자산.
- **이미 구현된 AIEO**(agents.md·UCP/MCP) — 신규 사이트에서 동등 이상으로 계승.
- **콘텐츠 생산 도구·KB**(디자인 스튜디오·인스타 카드뉴스·커피지식 KB).

### 3.4 데이터 흐름 (To-Be)

```
[관리자] 상품 1건 등록 (원두 프로파일 + key_color + 브랜드 노출)
        │  (자사몰 DB = 단일 소스)
        ├─▶ 스토어프론트 렌더: normcore / mtspace (브랜드·권한·가격 분기)
        ├─▶ 자산 자동생성(03 §14): 상세(네이티브)·블로그·라벨·카드뉴스·썸네일·인스타 → 검수 → 발행
        ├─▶ 동적 FAQ: 상품/정책 연결 FAQ + 변수(로스팅 월·화/출고/배송비) 주입
        ├─▶ 체크아웃: provider 어댑터(이니시스·카카오페이·페이팔) → 주문 paid → 재고 차감
        ├─▶ 회원: Supabase Auth(통합 계정), B2B 승인 → 차등가격(RLS)
        ├─▶ SEO/AIEO: SSR·JSON-LD(Product/FAQPage/Article)·sitemap·llms.txt·agents.md
        └─▶ 외부 채널 피드: 네이버·구글 머천트·인스타(단방향 동기화)
```

핵심 전환: 현행의 **Shopify=진실 + 3중 수작업** → 신규의 **자사몰 DB=진실 + 등록 1회로 사이트·자산·채널·FAQ 동시 반영**.

### 3.5 마이그레이션 매핑 (URL·데이터)

- **URL 보존**: `/products/{handle}`·`/collections/{handle}`·`/blogs/coffeelog-커피로그/*`·`/policies/*` 슬러그 유지 → 301 최소화(SEO 보호).
- **통합·폐기**: FAQ 4종 → 동적 FAQ(`/faq`)로 통합 + 301. AVADA HTML 사이트맵·cats·test 폐기. 통합 정책(`/pages/policy`) → 정책 페이지로 정리.
- **데이터**: 상품/변형/이미지·컬렉션(규칙→카테고리 정규화·**SKU 신규 부여**)·고객(비밀번호 제외, 재설정 안내)·주문(참조 보관)·블로그.
- **AIEO 계승**: agents.md·UCP/MCP·AI 디스커버리 사이트맵을 신규 스택에서 동등 이상으로 재구현.

## 4. 구현 접근(요약) 및 다음 단계

구현 순서는 03 §11 일정을 따른다: **Phase 0 기반(브랜드/스토어프론트 모델·스키마·Auth·도메인)** → **Phase 1 B2C 코어(카탈로그·체크아웃·멀티PG·동적FAQ·SEO)** → **Phase 2 이전·콘텐츠(301·정책·About)** → **Phase 3 B2B·차등가격** → **Phase 3.5 디자인 스튜디오·3.6 카드뉴스 엔진** → 컷오버.

크리티컬 패스: **데이터 모델 → 멀티 스토어프론트 → 멀티 PG → 가격해석/RLS**.

**바로 다음 단계 (사용자 합의 순서)**
1. **결정 잠그기** — 재고 정책·SKU 체계·페이팔 범위·통합 계정·카카오페이 경로(01 §9). → 별도 결정 체크리스트로 정리 가능.
2. **Supabase 스키마 초안(SQL 마이그레이션)** — 03 §2 데이터 모델을 실제 테이블·RLS·`resolve_price()`로. (Supabase 커넥터로 즉시 착수 가능)
3. 레포 스켈레톤(Next.js + 브랜드/스토어프론트 라우팅 + 디자인 토큰).
