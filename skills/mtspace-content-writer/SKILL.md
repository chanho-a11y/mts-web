1. **전체 패키지 위치.** 규칙 데이터, 스크립트, 상세 기준 문서는 대표 컴퓨터의
   `/Users/chanhohong/MTS/MTSPACE COFFEE/new-website/skills/mtspace-content-writer/` 에 있다(레포 mts-web 의 `skills/mtspace-content-writer/`).
   - 컴퓨터가 연결돼 있으면(device_bash) 그 폴더에서 바로 `python3 -I scripts/...` 를 돌린다.
   - 클라우드 작업 공간에서 돌려야 하면 그 폴더를 통째로 가져오거나, 레포를 클론해 같은 경로를 쓴다.
   - 둘 다 안 되면 아래 1~7절 요약 규칙으로 손으로 검수하고, 결과 머리에 "스크립트 검수 아님"을 적는다.

## 1. 모드 (요청 문장으로 판정)

| 모드 | 신호 | 하는 일 |
|---|---|---|
| 검토 | 봐 줘, 검수해 줘, 문제 있어? | 지적만. 원문 수정 안 함 |
| 채점 | 점수 매겨 줘 (요청 시만) | 채점표 점수와 등급 |
| 교정 | 고쳐 줘, 다듬어 줘, 교정해 줘 | 교정본 |

애매하면 검토로 시작하고 "고칠까요?" 한 줄을 붙인다.

## 2. 판정 코드

- **BLOCK 막음**: 사실 훼손(빠짐, 새로 생김), 보호 영역 변경(제품명, 레시피 수치, 가격, 고정 정보), 같은 글 중복, 건강 효능, 인증 무근거, 브랜드 혼입, 사용자 축 없음. 발행 보류.
- **FIX 고침**: 금지어, 명백한 오류, 형식 위반.
- **REVIEW 검토**: 의도에 따라 다름, 대표 승인 항목(아아 블렌드), 출처 없는 수치.
- **KEEP 유지**: 의도된 반복, 브랜드 말버릇, 금지어 때문에 지운 사실.

지적 한 줄 = `코드 + 규칙 + 찾은 말 + 고칠 방향`.

## 4. 공통 순서 (검토, 교정)

1. 매체를 정한다: `mall_blog | pdp | naver | instagram | b2b_doc | education | caption`. 짧은 글(공백 빼고 500자 미만, 캡션, 라벨, 번호 항목)은 `caption`.
2. 원문 검수: `python3 -I scripts/mtspace_check.py 원문 --channel 매체 --json 원문_검수.json`
   (금지어, 매체 형식, 항목 중복 3-gram 0.8 이상 = 막음, 핵심어 4개 이상 70% 공유 = 검토, K3 K4 K5 K7 지표, AI 상투, 사생활, 브랜드 에셋 4축)
3. 원문 사실 잠금: `python3 -I scripts/fact_lock.py lock 원문`
4. (채점+교정이면) 원문 점수를 먼저 확정해 적는다.
5. 교정: 짧은 글은 1개, 긴 글은 최소, 중간, 적극 세 본(versions.md). "세 버전" 요청이면 짧은 글도 세 본.
6. 교정본마다 `python3 -I scripts/fact_lock.py diff 원문 교정본`
   전체 빠짐이나 새로 생김 = 막음(종료 코드 1). 항목별 빠짐 = 검토. 금지어 때문에 지운 사실 = 의도된 삭제.
   교정본도 `mtspace_check.py` 로 다시 돌려 막음 0, 고침 0 을 만든다.
7. 긴 글 산출물: `python3 -I scripts/build_outputs.py --title 제목 --channel 매체 --orig 원문 --min 최소 --mid 중간 --max 적극 --out 출력폴더 [--mark ch_logo.png] [--scores 점수.json]`
   → 세 본 DOCX + 비교 PDF(판정 요약, 사실 대조 표, 지적 목록, 나란히 보기) + 검수 JSON. 양식은 chanho-document-design(그레이스케일). ch. 마크 PNG 가 없으면 마크 없이 만들고 [확인 필요]를 남긴다(글자로 흉내 내지 않는다).
8. 보고: 판정 요약 한 단락 + 막음과 고침 목록 + 산출물. 비교 PDF 를 쪽마다 이미지로 떠서 직접 확인한 뒤 보낸다.

## 5. 초안 흐름

1. **사실 카드**: 매체와 독자, 목표 행동(납품 문의, 사업자 가입), 제품명, 산지, 생산자, 품종, 가공, 고도, 로스팅, 컵 노트, 레시피, 가격(필요 시), 공개 배합비, 쓰는 사람의 장면, 출처. 칸마다 출처를 적고 모르는 칸은 [확인 필요].
2. **개요 + 제목 후보 3** (싱글 오리진은 D-123 구조).
3. **담당자 승인 관문**: 대표가 승인해야 본문으로 간다. 수정 지시는 승인이 아니다. 승인 전에는 본문을 쓰지 않는다.
4. **초안**: 문장마다 사실 카드 근거로. 매체 규칙과 톤을 따른다.
5. **근거 감사**: 근거 없는 사실 문장 = 막음. `mtspace_check.py` 막음 0, 고침 0. `fact_lock.py lock` 결과가 사실 카드 밖이면 막음.

## 7. 판단 기준 요약

- **교정은 사실을 더하거나 빼지 않는다.** 모르는 사실은 [확인 필요].
- **브랜드 에셋 4축**: A1 쓰는 사람(카페, 바리스타, 홈카페의 하루), A2 원두(산지, 가공), A3 로스팅(포인트, 일관성), A4 추출(레시피, 숫자). 블로그, 네이버, 인스타, B2B 문서에서 A1 이 없으면 발행 보류.
- **문장**: 결과 먼저, 주어는 독자, 포괄 동사(지원, 제공, 보조, 진행)는 실제 동사로, 같은 종결 네 문장 연속 금지, 90자 넘는 문장은 나눈다.
- **톤**: B2B 와 소비자 두 갈래(versions.md). 사실 기반, 절제, 조용한 자신감.
- **USP 한 줄**: 라이트든 다크든, 캐릭터는 에티오피아 (D-120). 싱글 오리진은 라이트 로스팅.
- **대표 이력**: 바리스타 컴페티터, 입상 14회(전체 수상 이력 19개).
- **채점**(요청 시만): M1 사실 20(하한 20), M2 쓰는 사람 20(12), M3 근거 15(9), M4 톤과 금지어 15(12), M5 매체 형식 10(6), M6 한국어 10(6), M7 AI 상투 5(3), M8 표시 광고 5(5). 하한 미달이면 발행 보류. A 90 이상, B 80, C 70, D 60, F 미만.

- 회귀: 규칙이나 스크립트를 바꾸면 `python3 -I tests/run.py` 가 PASS 여야 한다.
- 이 스킬의 문장에도 긴 줄표와 가운뎃점을 쓰지 않는다.
