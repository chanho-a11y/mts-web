# 작업 모드, 판정 코드, 출력 분기

## 모드 4종 (요청 문장으로 판정)

| 모드 | 이럴 때 | 하는 일 | 원문 수정 |
|---|---|---|---|
| 검토 | "봐 줘", "괜찮은지", "문제 있어?", "검수해 줘" | 지적 목록만 낸다 | 안 함 |
| 채점 | "점수 매겨 줘", "몇 점이야" (요청이 있을 때만) | scoring.md 채점표로 점수와 등급 | 안 함 |
| 교정 | "고쳐 줘", "다듬어 줘", "교정해 줘" | 교정본을 낸다 | 함 |
| 채점+교정 | "점수 보고 고쳐 줘" | 원문 점수를 먼저 고정한 뒤 교정, 교정본 점수를 다시 매긴다 | 함 |

애매하면 검토로 시작하고 "고칠까요?" 한 줄을 붙인다. 초안 작성 요청은 drafting.md 흐름으로 간다.

## 판정 코드

| 코드 | 이름 | 기준 | 발행 |
|---|---|---|---|
| BLOCK | 막음 | 사실 훼손(빠짐, 새로 생김), 보호 영역 변경(제품명, 레시피 수치, 가격, 고정 정보), 같은 글 중복, 건강 효능, 인증 무근거, 브랜드 혼입, 사용자 축 없음 | 보류 |
| FIX | 고침 | 금지어, 명백한 오류(맞춤법, 구표기, 형식 위반) | 고치면 가능 |
| REVIEW | 검토 | 의도에 따라 다름, 대표 승인 항목(아아 블렌드), 출처 없는 수치 | 담당자 판단 |
| KEEP | 유지 | 의도된 반복, 브랜드 말버릇, 금지어 때문에 지운 사실 | 그대로 |

지적은 모두 `코드 + 규칙 + 찾은 말 + 고칠 방향` 한 줄로 쓴다.

## 출력 분기

| 조건 | 출력 |
|---|---|
| 짧은 글 (공백 빼고 500자 미만, 번호 항목, 캡션, 라벨, 상품 한 줄) | 교정본 1개 + 지적 목록 (채팅 안) |
| 짧은 글인데 "세 버전" 요청 | 세 본 (채팅 안) |
| 긴 글 | 세 본(최소, 중간, 적극) + DOCX 3개 + 비교 PDF + 검수 JSON (`scripts/build_outputs.py`) |

세 본의 성격은 versions.md.
